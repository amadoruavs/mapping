# Performance work

Correctness and visual quality come first. The current NumPy/OpenCV implementation is the reference; timings are saved per run. No claim of constant or sublinear total runtime is possible when every input pixel must be read, indexed, and potentially emitted.

The Metal/MPS backend is now implemented. See [architecture, numerical policy, and measurements](docs/METAL_BACKEND.md). It uses an in-process native library, persistent shared buffers, MPS matrix products and separable filtering, and custom MSL for matching, warping, reductions, sampling, tile packing, and lighting. `--recompute-warps` avoids compositor intermediates on disk by rerunning the fused warp in the selection pass. The following list distinguishes remaining work from completed acceleration.

1. Replace quadratic thumbnail duplicate screening with signature buckets plus a spatial/image descriptor index; keep the final duplicate decision conservative.
2. Use bounded footprint overlap degree and persistent feature caches. Candidate discovery can approach O(n log n + k), but k can itself grow quadratically if every image overlaps every other image. Local fallback uses O(n × sequence_window) candidates and can miss nonsequential loop closures.
3. Cache stage artifacts by input hash, calibration, metadata, and algorithm version. Currently only pair-registration reuse is fingerprinted. Correct cache invalidation matters more than saving a few seconds.
4. Stream fixed-size output tiles with halos. The current compositor streams each image's bounding box but keeps whole-map mean and selection arrays. Output-tile scheduling will bound memory independently of map area and avoid touching empty image footprints. Avoid materializing n×H×W.
5. Batch hash records and store packed coordinate keys with a multivalue observation list. Raw RGB tile storage is roughly three bytes per input pixel, plus indexing/padding. Compression and content-addressed source-tile references can trade disk space for decoding cost.
6. Implemented GPU rectification, NCC reductions, exact descriptor matching, overlap statistics, and Gumbel selection with CPU equivalence tests. The old file-based lighting runner remains a historical harness; the pipeline uses the persistent native library. SIFT extraction and sparse global alignment remain CPU work.
7. Implemented resident light environments in bounded stripes, GPU normals/shadows, MPS visibility filtering, selection, and fused export. Flat lighting collapses identical environments to one pass. Further tuning should profile command scheduling and precision on each target device; float16 compute is not enabled without an error budget.
8. Use Metal on Apple platforms and evaluate a Vulkan/OpenCL compute backend for the target Radeon laptop's actual OS/driver. Keep the CPU implementation as a supported fallback. Benchmark 39, 100, 300, and 450 frames at identical native resolution and overlap, tracking wall time, peak memory, disk traffic, and visual alignment.
9. Upgrade geometry when needed: calibrated lens distortion, rolling-shutter correction, actual per-frame altitude, bundle adjustment, and an ODM-derived DSM/mesh. These affect correctness and cannot be replaced with a faster shader.
10. Test strict corner vocabulary on representative overlap/rotation/lighting conditions. The sample's 2% criterion is too strict for reliable acceptance; do not silently loosen it. Consider additional interior patches or descriptors as a separately measured design change.

`scripts/validate_metal.py` checks accelerated stages and the geographic pipeline. `scripts/benchmark_metal.py` records local stage throughput with host exchange included. These measurements do not establish performance on the future laptop or on a 300–450-frame flight.
